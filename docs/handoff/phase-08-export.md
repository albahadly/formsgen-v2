# Phase 08 — CSS adapters, ExportTarget plugins, export dialog

## Status

Complete — 2026-10-04, commit: see `git log` (feat(phase-08)).

## What was built

- **CSS framework adapters** — `src/export/css/`: `CssFrameworkAdapter` contract (`classes(slot)`, `cell(span)`, `invalidClass`, `stylesheet?`, `assets`, `readmeNote`) with three implementations: vanilla (emits a full self-contained stylesheet with the form's theme tokens baked in, mirroring the renderer's CSS), Tailwind (stock utilities, no plugin), Bootstrap 5 (real idioms: `form-control`, `form-select`, `form-check`, `is-invalid`, `row`/`col-*`). No emitter or scaffold contains a literal class name.
- **Logic compilers** — `src/export/compile.ts`: rules and conditions compile to JS source (`compileValidator`, `compileConditions`, shared `RUNTIME_HELPERS`); `src/export/logic.ts`: visibility functions, validators literal, and the submit-payload expression (conditional spreads; hidden fields excluded — renderer semantics).
- **Markup walker** — `src/export/markup.ts`: renders the tree (grids, cells with spans, group fieldsets, columns, conditional wrappers) via the adapter; leaf fields delegate to **registry emitters** — `ElementDefinition.export.{vue,html}` added to text/textarea/select/checkbox (`registry/emitters/shared.ts` holds the building blocks).
- **Export targets** — `src/export/targets/` plugin registry (`registerTarget`/`listTargets`):
  1. `json` — canonical schema, round-trips through the parser.
  2. `vue-lib` — SFC using `@formsgen/renderer` with inlined schema.
  3. `vue-standalone` — ZERO-DEP SFC: reactive data, compiled validators (blur + revalidate-after-touch + submit), visibility functions, conditional-spread payload, optional `meta.submit` fetch, scoped stylesheet in vanilla mode.
  4. `html` — one self-contained document: `data-fg-path/kind` controls, generic runtime + compiled validators/conditions/payload, CDN links for tailwind/bootstrap, embedded CSS for vanilla.
- **Export dialog** — `components/export/ExportDialog.vue` (lazy-loaded chunk): target tabs, framework select (hidden for non-framework-aware targets), file tabs incl. a README tab, highlighted code (`components/ui/CodeBlock.vue`, shared with the code view), Copy / Download / **Download .zip** (jszip; files + generated README). Header **Export** button opens it.
- **Tests** — 114 total (42 renderer / 72 builder). New: behavioral compile tests executing generated JS via `new Function` against the renderer's semantics table; target-registry tests (every target × every framework produces files + README); snapshots for vue-standalone and html × 3 frameworks; idiom assertions (bootstrap has `form-control`, never `fg-input`); syntax check of the generated HTML script.
- **Browser-verified**: the generated vanilla HTML export was exercised end-to-end in Chromium from `file://` — conditional show/hide, blocked invalid submit, regex-on-blur, and the exact expected nested payload.

## What was intentionally NOT done

- React and Blazor targets → phase 9 (the registry + emitter map are ready; §7b of the master prompt).
- Renderer **class presets** (`preset="tailwind|bootstrap"` on `FormsGenForm`) → deferred; the adapters currently serve codegen only. Revisit when someone needs the live renderer with another framework (REBUILD_PROMPT §4). Record: this is the one §7a item not yet wired both ways.
- Vue-standalone compile-check via `vue-tsc` in CI → snapshots + behavioral compile tests cover it today; add a `tsc`-based check in phase 9 alongside React's (one harness for both).
- `vue-lib` ignores the framework selector by design (renderer presets don't exist yet) — `frameworkAware: false`.

## Key decisions & why

- **Container markup is generated by the shared walker, not per-element emitters** — group/columns markup is pure structure; emitters stay leaf-only (checkbox/text/etc.). Matches ADR-0001's spirit: structure is engine-side.
- **Two trust-boundary v-html sinks stay sanctioned** (SvgIcon, CodeBlock) — CodePanel now reuses CodeBlock, so hljs setup lives in ONE file.
- **Field visibility functions use the FULL inherited condition chain**; payload additionally wraps conditional containers so a hidden named group disappears entirely (matches `pickVisibleData`).
- **`</script>` needs escaping only inside .vue SFC source** — in .ts template literals write it plainly (`no-useless-escape` enforces this).
- **ExportDialog is an async component** to keep jszip + hljs out of the main bundle (main ≈ 430 kB, dialog chunk ≈ 126 kB, no Vite size warning). In tests, `flushPromises()` after opening resolves it.


1. JSON tab → download, then Open it back into the builder (round-trip).
2. "Vue (standalone)" + Bootstrap 5 → markup shows `form-control`/`is-invalid`; vanilla shows `<style scoped>`; README tab shows install steps.
3. "HTML + JS" + vanilla → Download, open the file in any browser: validation, conditions and submit payload all work with no network.
4. Download .zip → contains the artifact plus README.md.

## Known issues / gotchas

- Snapshot files live in `src/export/targets/__snapshots__/` — review diffs deliberately when emitters change; don't blind-update.
- The HTML export's listeners use `focusout` (blur doesn't bubble); keep that if you touch the runtime.
- The temporary pattern for browser-E2Eing generated artifacts: write a throwaway vitest file that saves outputs to /tmp, run it, delete it, then drive Playwright at `file:///tmp/...` (see phase-04 handoff for the Playwright invocation details).
- `vue-standalone` conditional `v-if` attributes are single-quoted because compiled expressions contain double-quoted JSON strings.
